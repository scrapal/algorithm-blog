## 什么是 KMP？
先来看一道题：

> 给出两个字符串 $s_1$ 和 $s_2$，若 $s_1$ 的区间 $[l, r]$ 子串与 $s_2$ 完全相同，则称 $s_2$ 在 $s_1$ 中出现了，其出现位置为 $l$。  
> 现在请你求出 $s_2$ 在 $s_1$ 中所有出现的位置。
>
> 对于全部的测试点，保证 $1 \leq |s_1|,|s_2| \leq 10^6$，$s_1,s_2$ 中均只含大写英文字母。

我们很容易就能想到 $\mathcal{O}(|s_1|\cdot|s_2|)$ 的暴力：  
循环枚举 $i$（$1\le i\le|s_1|-|s_2|+1$），检查 $s_1[i\ldots i+|s_2|-1]$ 是不是 $s_2$，如果是就输出 $i$（使用 `1-based` 下标）。无论本次是否匹配成功，之后都从 $i+1$ 开始检查下一个可能的起点。

但是注意到 $1 \leq |s_1|,|s_2| \leq 10^6$，这种方法显然会超时。  
于是就有三位大神提出了另一种以 $\mathcal{O}(|s_1|+|s_2|)$ 时间复杂度解决这种匹配字符串的问题的算法，叫做 **KMP**。

::: details 小知识

KMP 算法由三位计算机科学家共同提出：

- Donald Knuth
- James H. Morris
- Vaughan Pratt

KMP 就是三人姓氏首字母的组合。

:::

## KMP 的核心思想

举个栗子，文本串和模式串分别为：

```text
文本串：A B A B A B A C
模式串：A B A B A C
                ↑
```

前 $5$ 个字符 `ABABA` 已经对上了，但是到第 $6$ 个字符时文本串中的 `B` 和模式串中的 `C` 不一样，发生了失配。

如果暴力就会先把模式串向右移动一位，然后再从第一个字符重新比较。但是，之前的比较已经告诉了我们文本串中的这一段内容是 `ABABA`，重新逐个比较其中的字符显然有些浪费。

观察一下已经匹配成功的部分 `ABABA`：

```text
ABABA
^^^    前缀 ABA
  ^^^  后缀 ABA
```

它的**真前缀** `ABA` 和**真后缀** `ABA` 相同。所以如果失配了，就可以直接把模式串开头的 `ABA` 移动到真后缀 `ABA` 的位置。

```text
文本串：A B A B A B A C
模式串：    A B A B A C
```

这样前面的 `ABA` 就不需要重新比较，可以直接从后面的字符继续匹配。

::: details 真前缀与真后缀

对于一个字符串 $s$，从第一个字符开始连续选取若干个字符得到的字符串称为
$s$ 的前缀。比如字符串 `ABA` 的所有非空前缀为：

```text
A
AB
ABA
```

如果一个前缀不等于字符串本身就称它为**真前缀**。所以 `ABA` 的所有非空真前缀就是：

```text
A
AB
```

后缀同理，字符串 `ABA` 的所有非空后缀为：

```text
A
BA
ABA
```

`ABA` 的所有非空**真后缀**为：

```text
A
BA
```

如果一个字符串没有非空的相同真前后缀，就把长度记为 $0$。下文的前缀与后缀都指真前缀与真后缀。

:::

在匹配失败时利用已经匹配部分的最长相同前后缀，把模式串移动到下一个可能匹配成功的位置就是 KMP 的核心思想。这样文本串的下标就不需要向前回退了。可能看起来还是有点一头雾水的，接下来我们看看具体是怎么操作的。

## 具体实现

定义 $nxt[i]$ 表示 $p[1\ldots i]$ 的最长相同真前后缀长度。以 `"ababaca"` 为例：

| $i$ | $nxt[i]$ | 最长相同真前后缀 |
| :---: | :---: | :---: |
| 1 | 0 | `""` |
| 2 | 0 | `""` |
| 3 | 1 | `"a"` |
| 4 | 2 | `"ab"` |
| 5 | 3 | `"aba"` |
| 6 | 0 | `""` |
| 7 | 1 | `"a"` |

其中 `nxt[i]=0` 表示 $p[1\ldots i]$ 没有非空的相同真前后缀，表格中的 `""` 表示空字符串。

这里先说明一下后面经常出现的 $j$。$j$ 表示模式串已经匹配好的长度，也就是说 $p[1\ldots j]$ 已经匹配完成，接下来要匹配的是 $p[j+1]$。

我们先不管这个数组是怎么算出来的，我们先看看它有什么用。  
还是使用刚才的例子：

```text
文本串：A B A B A B A C
模式串：A B A B A C
                ↑
```

当失配时我们查看模式串当前已经匹配的 `ABABA`，这个子串的最长相同真前后缀长度就是模式串的 $nxt[5]$，也就是 $3$（`ABA`）。把这个串的前缀移动到对应后缀的开头，能保证新位置的前缀已经匹配完成，因为它与原本后缀的内容完全相同，而原本的后缀又已经匹配好了。所以就不需要再从头匹配一次了。

此时原本已经匹配了 $5$ 个字符，也就是 $j=5$。移动后令 `j=nxt[5]=3`，表示前 $3$ 个字符已经匹配好了。注意，文本串的位置没有改变，还是用刚才的第 $6$ 个字符 `B` 去匹配新的 $p[j+1]$，也就是模式串的第 $4$ 个字符 `B`。

如何把这个串的前缀移动到后缀的位置呢？很简单，设当前已经匹配好的长度为 $j$，我们知道后缀的长度是 $nxt[j]$，所以它的开头位置就是 $j-nxt[j]+1$。同时，前缀的开头是模式串第一个字符的位置，所以后缀与前缀的距离就是 $j-nxt[j]+1-1=j-nxt[j]$。每次失配只需要把模式串向右移动 $j-nxt[j]$ 个位置再继续匹配。如果移动后仍然失配，就继续尝试更短的相同真前后缀，直到当前字符匹配成功或者 $j=0$。

实际实现时不需要真的移动模式串。模式串向右移动 $j-nxt[j]$ 位，等价于直接令 `j=nxt[j]`，表示保留前 `nxt[j]` 个已经匹配的字符，然后继续用文本串当前的字符进行匹配。

那么接下来就要考虑 `nxt` 数组怎么算出来了。
我们从左到右计算 `nxt` 数组。显然长度为 $1$ 的字符串不存在非空真前后缀，因此 `nxt[1]=0`。

接下来思考如何计算 `nxt[i]`。此时 `nxt[1]` 到 `nxt[i-1]` 都计算完了。

令 `j=nxt[i-1]`。

这表示 $p[1\ldots i-1]$ 存在长度为 $j$ 的最长相同真前后缀，就是 $p[1\ldots j] = p[i-j\ldots i-1]$。现在我们想知道这组前后缀可不可以继续延长，所以需要比较两个前后缀后面的字符，也就是比较 $p[j+1]$ 和 $p[i]$。

可能有人会发现，代码中并没有在每轮循环开头写 `j=nxt[i-1]`。这是因为上一轮结束时已经执行了 `nxt[i-1]=j`，所以进入下一轮时，`j` 本来就等于 `nxt[i-1]`。

### 两个字符相同

如果 `p[j+1]==p[i]`，说明原来的相同真前后缀可以继续延长一个字符，因此 `nxt[i]=j+1`。比如说计算 `p="ababa"` 的 `nxt[5]` 时，已经知道 `nxt[4]=2`，此时长度为 $2$ 的相同真前后缀是 `ab`。比较：

```text
p[3] = a
p[5] = a
```

两个字符相同，所以就把 `ab` 延长为了 `aba`，`nxt[5]=3`。

### 两个字符不同

如果 `p[j+1]!=p[i]`，说明长度为 $j$ 的相同真前后缀无法继续延长。

但是，这**并不代表不存在更短的相同真前后缀**。我们还需要尝试：

```cpp
j=nxt[j];
```

`nxt[j]` 表示 $p[1\ldots j]$ 的最长相同真前后缀长度，它就是接下来最有可能匹配成功的、更短的前后缀。因为 $p[1\ldots j]$ 已经匹配成功了，所以想保留一部分已经匹配的内容，这一部分就必须既是它的前缀，也是它的后缀，而其中最长的长度正好就是 `nxt[j]`。

如果仍然失配，就继续执行：

```cpp
j=nxt[j];
```

直到找到能够匹配的位置，或者 `j=0`。整个过程可以写成：

```cpp
while(j&&p[i]!=p[j+1])j=nxt[j];
if(p[i]==p[j+1])j++;//如果新的位置和前缀的下一项相同就把长度增加1
nxt[i]=j;
```

比如计算 `p="ababaca"` 的 `nxt[6]`，一开始有 `j=nxt[5]=3`：

```text
p[4] = b，与 p[6] = c 不同，令 j = nxt[3] = 1
p[2] = b，与 p[6] = c 不同，令 j = nxt[1] = 0
p[1] = a，与 p[6] = c 不同
```

最后没有找到能够继续延长的前后缀，所以 `nxt[6]=0`。代码中的 `while` 循环做的就是这个不断缩短前后缀的过程。

### 找到完整匹配之后

匹配时如果 `j==m`，说明整个模式串都匹配完了。因为这次匹配在文本串的第 $i$ 个字符结束，模式串的长度又是 $m$，所以起点就是 $i-m+1$。

输出答案后不能直接设置 `j=0`，因为两次匹配可能会重叠。比如模式串 `AAA` 在文本串 `AAAAA` 中出现的位置是 $1,2,3$。设置 `j=nxt[j]` 就可以保留结尾处已经匹配好的部分，接着寻找下一次匹配。

这样 $nxt$ 数组的设置和后面的查找逻辑就都完成了，接下来来看看代码吧。

## 代码
```cpp
#include<bits/stdc++.h>
using namespace std;

const int N=1000005;
int nxt[N]; //记录最长相同真前后缀长度

int main()
{
    string s,p;
    cin>>s>>p;

    s=" "+s;//1-based下标
    p=" "+p;
    int n=s.size()-1;
    int m=p.size()-1;

    for(int i=2,j=0;i<=m;i++)
    {
        while(j&&p[i]!=p[j+1])j=nxt[j];//只要新一项不相等就不断缩小范围到更短的前后缀
        if(p[i]==p[j+1])j++;//如果新的位置和前缀的下一项相同就把长度增加1
        nxt[i]=j;//设置nxt数组
    }

    for(int i=1,j=0;i<=n;i++)
    {
        while(j&&s[i]!=p[j+1])j=nxt[j];//只要新一项匹配不上就不断缩小范围到更短的前后缀
        if(s[i]==p[j+1])j++;//如果匹配上了就把要匹配的位置设为下一项

        if(j==m)//模式串匹配完了
        {
            cout<<i-m+1<<"\n";//在i-m+1开头的位置出现了一次模式串
            j=nxt[j];//再回到前缀结尾继续匹配
        }
    }
    return 0;
}
```

## 复杂度分析

构造 `nxt` 数组时，$i$ 只会从左到右移动。每轮循环最多让 $j$ 增加 $1$，而 `while` 每执行一次都会让 $j$ 减小。$j$ 总共增加的次数不超过 $|p|$，所以它总共减小的次数也不会超过 $|p|$，时间复杂度就是 $\mathcal{O}(|p|)$。

匹配时也是一样的。文本串下标 $i$ 不会回退，$j$ 增加和减小的总次数都不会超过 $|s|$，所以匹配的时间复杂度为 $\mathcal{O}(|s|)$。

所以 KMP 的总时间复杂度为：

$$
\mathcal{O}(|s|+|p|)
$$

`nxt` 数组需要保存模式串每个前缀的答案，所以空间复杂度为 $\mathcal{O}(|p|)$。

## 例题

### [P4391 [BalticOI 2009] Radio Transmission 无线传输](https://www.luogu.com.cn/problem/P4391)

这道题需要利用 `nxt` 数组求字符串的最短循环节，可以帮助我们进一步理解最长相同真前后缀的作用。

::: details 题解

设字符串长度为 $n$，`nxt[n]` 是整个字符串的最长相同真前后缀长度，那么最短周期为：

$$
n-nxt[n]
$$

例如字符串 `ababab` 的最长相同真前后缀是 `abab`，长度为 $4$，所以它的最短周期为 $6-4=2$，对应的循环部分是 `ab`。

下面说明为什么这个结论成立。设：

$$
L=nxt[n],\qquad T=n-L
$$

因为长度为 $L$ 的前缀和后缀相同，所以：

$$
p[1\ldots L]=p[T+1\ldots n]
$$

也就是说，对于 $T+1\le i\le n$，都有 $p[i]=p[i-T]$。将字符串向右移动 $T$ 位后，重叠部分完全相同，因此 $T$ 是它的一个周期。

如果还存在一个更短的周期 $T'<T$，那么字符串就会存在长度为 $n-T'$ 的相同真前后缀。由于 $n-T'>n-T=L$，这与 $L$ 已经是最长相同真前后缀矛盾。因此，$T=n-nxt[n]$ 就是最短周期。

需要注意，P4391 允许最后一个循环是不完整的。例如 `ababa` 可以看作 `ab` 不断重复后得到的字符串的前缀，因此本题直接输出 `n-nxt[n]`，不需要判断它能否整除 $n$。

如果题目要求原字符串必须由若干个完整循环节拼成，则还需要判断：

```cpp
int ans=n-nxt[n];
if(n%ans!=0)ans=n;
```

本题的核心代码为：

```cpp
for(int i=2,j=0;i<=n;i++)
{
    while(j&&s[i]!=s[j+1])j=nxt[j];
    if(s[i]==s[j+1])j++;
    nxt[i]=j;
}
cout<<n-nxt[n];
```

### [P4824 [USACO15FEB] Censoring S](https://www.luogu.com.cn/problem/P4824)

这道题要求不断删除文本串中出现的模式串。删除一次后，原本不相邻的两部分会连接起来，因此可能产生新的匹配。

::: details 思路提示

使用栈保存当前没有被删除的字符，并记录每个字符入栈后 KMP 已经匹配的长度。匹配完整模式串时，将栈顶对应的字符删除，再恢复到删除前的匹配状态。

:::
